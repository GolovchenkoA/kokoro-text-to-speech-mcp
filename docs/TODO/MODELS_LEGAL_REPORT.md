# TTS Models — Commercial Use / Resale Legal Report

*Prepared: 15 November 2026. Scope: can each model be used for revenue generation when sold as part of another app?*

> **Disclaimer:** This is a research briefing, not legal advice. Have a lawyer review it before launch.

**Method:** Checked official Hugging Face model cards and license files, publisher announcements, and the actual PyPI packages with their dependency chains (unpacked and inspected wheel metadata).

---

## Summary

| Model | License | Risk for resale inside your app | Main issue |

## 1. Kokoro-82M and kokoro==0.9.4

**Weights — OK.** The Hugging Face repo `hexgrad/Kokoro-82M` is tagged Apache 2.0. The model card states it is an Apache-licensed model deployed in numerous projects and commercial APIs.

**Python package 0.9.4 — GPL problem.** Dependency chain verified from the actual wheels:

- `kokoro 0.9.4` — Apache 2.0, but hard-requires `misaki[en]>=0.9.4`.
- `misaki[en]` requires `phonemizer-fork` — **GPL-3.0-or-later**.
- `misaki[en]` also requires `espeakng-loader`, which **bundles `libespeak-ng.so`** — espeak-ng is GPL-3.
- These are imported directly into your Python process. Shipping this inside a distributed app can arguably require releasing your app's source under the GPL. The model author acknowledged this in a Hugging Face discussion: it could be problematic for closed-source commercial software.

**Training-data note.** The model card lists synthetic audio generated by closed TTS models from large providers among its training sources. Those providers' terms typically forbid training competing models on their output. Any breach would be the trainer's, not yours, but training-data provenance is not fully clean. The card also lists CC BY audio (SIWIS — CC BY 4.0, Koniwa — CC BY 3.0); crediting these in your app's notices is cheap insurance.

**What to do:** Use the weights, but replace the default text-to-phoneme front end with non-GPL code, or run espeak-ng as a separate server process (GPL is generally not triggered when software only runs as a service and is not distributed).

## 2. MOSS-TTS-Nano (OpenMOSS)

License statements conflict:

- Hugging Face metadata for `OpenMOSS-Team/MOSS-TTS-Nano-100M` and `OpenMOSS-Team/MOSS-Audio-Tokenizer-Nano`: **Apache 2.0**. GitHub mirrors report Apache License 2.0.
- But the model's own README says: *"This repository will follow the license specified in the root LICENSE file. If you are reading this before that file is published, please treat the repository as not yet licensed for redistribution."*
- The Hugging Face model repo contains **no LICENSE file**.
- Training data is not documented. A comparable 2026 model (OmniVoice) had to license its weights CC-BY-NC due to training-data constraints (Emilia dataset).

**What to do:** Confirm the LICENSE file in the GitHub repo and, ideally, get written confirmation from OpenMOSS that the weights are Apache 2.0 for commercial use before shipping.

## 3. Qwen3-TTS-0.6B (Alibaba)

**Clean.**

- Technical report (arXiv 2601.15621): tokenizers and models released under Apache 2.0.
- Hugging Face metadata for `Qwen3-TTS-12Hz-0.6B-Base`, `0.6B-CustomVoice`, and `Qwen3-TTS-Tokenizer-12Hz`: Apache 2.0.
- `qwen-tts` package: Apache 2.0. No GPL dependencies found; no extra usage terms.

**Obligations:** Standard Apache 2.0 — include license text and any NOTICE file; mark modified files.

## 4. Supertonic 3 (Supertone)

**Commercial use allowed, with conditions.** Sample code is MIT; weights are under the **BigScience Open RAIL-M License** (dated 18 Aug 2022). Key terms from the license text:

- **Rights:** perpetual, worldwide, royalty-free, irrevocable license to reproduce, sublicense and distribute the model. Hosting as a service is explicitly allowed.
- **Pass-through requirement (§4a):** the use-based restrictions (Attachment A) must be included as an enforceable provision in any legal agreement governing use or distribution of the model. **Your app's terms of use must include them.** You must also give recipients a copy of the license and retain notices.
- **AI-disclosure clause (Attachment A(e)):** you may not disseminate generated content without expressly and intelligibly disclaiming that it is machine-generated. A read-aloud product needs visible "AI-generated voice" labeling.
- Other banned uses include impersonation without consent, medical advice, and law-enforcement/immigration profiling.
- **Update clause (§7):** you must make reasonable efforts to use the latest version — awkward because Supertone **discontinued** the open-source Supertonic project (GitHub archived; Voice Builder unavailable after 31 Aug 2026).
- **Trademarks (§8):** "Supertonic" and "Supertone" are not licensed — don't use them in your branding.

## 5. Chatterbox Multilingual v3 (Resemble AI)

**License — OK.** The official repo `ResembleAI/chatterbox` and the `chatterbox-tts` package (0.1.7) are **MIT**. The August 2026 commercial retirement does not change this: Resemble states the models remain open and free to build on under Voice AI Research, but are no longer offered as commercial paid products. An MIT grant on already-published weights cannot be withdrawn.

**Issues:**

- **GPL dependency:** `chatterbox-tts` requires `pykakasi==2.3.0` — **GPL-3.0-or-later** (used for Japanese). Fix: install without that dependency and drop Japanese, or run the model as a separate service.
- **Llama base:** described as a "0.5B Llama backbone", with Llama 3 credited in the acknowledgements. Meta never released a 0.5B Llama, so this most likely means Resemble used the Llama architecture and trained the weights themselves, in which case Meta's license would not apply. *This is an inference, not a statement from Resemble.*
- **Training data:** not documented beyond "prompts are sourced from freely available data on the internet".
- **No support or updates.** Resemble recommends against commercial deployment for Korean and Vietnamese in v3.

## Applies to all models: EU AI Act

Selling an AI voice system on the EU market (Poland): since **2 August 2026**, AI systems placed on the market must mark generated output in a machine-readable format — in practice, a watermark on generated audio.

- Chatterbox has a built-in watermark (PerTh) — keep it on.
- For the other four, add watermarking yourself. Resemble's PerTh library is MIT-licensed and could be reused.

---

## Recommendation

1. **Qwen3-TTS** — safest; ship-ready.
2. **Chatterbox v3** and **Kokoro** — fine once the GPL pieces are handled (`pykakasi` for Chatterbox; espeak-ng/phonemizer for Kokoro).
3. **Supertonic 3** — only if you add the pass-through restrictions to your terms and label output as AI-generated.
4. **MOSS-TTS-Nano** — hold until the license is confirmed in writing.

**Before launch, have a lawyer review:** (a) the GPL question for whatever you actually distribute to users; (b) EU AI Act compliance.

## Status in the app

Of the models in this report only **Kokoro-82M** (default) and **Qwen3-TTS 0.6B CustomVoice** are in `models.json`. Chatterbox, MOSS-TTS-Nano and Supertonic 3 are not added. Qwen3-TTS is used for plain text-to-speech with its preset voices (no voice cloning). It was implemented from the Qwen3-TTS README and tested with fakes only; the open checks are listed in `docs/TODO/multi-models-support.md` (2.3). The EU AI Act watermarking point above is not implemented for any model.
